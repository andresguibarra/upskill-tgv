# Días 7 y 8: testing frontend con Vitest y Vue Test Utils

Los patrones que más se usan, cada uno con un test real en [`frontend/src/dia-07/__tests__/dia-07.spec.ts`](../frontend/src/dia-07/__tests__/dia-07.spec.ts). Se corren con `npx vitest run` (o `npm run test:unit` en modo watch).

## Lo básico: montar, interactuar, esperar

```ts
const wrapper = mount(Comp, { props: { delay: 100 } })
await wrapper.get('input').setValue('vue')     // dispara input + v-model
await wrapper.get('button').trigger('click')
await flushPromises()                          // resuelve promesas pendientes (fetch, async)
expect(wrapper.emitted('search')).toEqual([['vue']])
```

> `get` falla si no encuentra el elemento y `find` devuelve un wrapper vacío (usalo con `.exists()`). `await` en `setValue`/`trigger` espera el re-render (`nextTick`); `flushPromises` hace falta cuando hay promesas propias.

## Timers falsos

```ts
beforeEach(() => vi.useFakeTimers())
afterEach(() => vi.useRealTimers())

vi.advanceTimersByTime(299)   // todavía no
vi.advanceTimersByTime(1)     // ahora sí
vi.runAllTimers()             // vacía la cola
```

> Debounce, throttle, polling y toasts se testean sin esperar tiempo real. Siempre volver a timers reales en `afterEach`.

## Dependencias inyectadas: `global.provide`

```ts
mount(SaveButton, {
  props: { save },
  global: { provide: { [NotifierKey as symbol]: { notify } } },
})
```

> Reemplaza a `app.use(plugin)` en el test. Con `global.plugins: [createNotifier(fn)]` se instala el plugin real.

## Slots y `v-model`

```ts
mount(SelectList<User>, {
  props: { items, modelValue: null, 'onUpdate:modelValue': (v) => wrapper.setProps({ modelValue: v }) },
  slots: { item: `<template #item="{ item, selected }">{{ item.name }}</template>` },
})
```

> Para `v-model` se pasa la prop y su `onUpdate:` a mano. `mount(Comp<User>, …)` fija el genérico del componente.

## Aislar al padre: `stubs` y `findComponent`

```ts
const wrapper = mount(UserPicker, { props: { users }, global: { stubs: { SelectList: true } } })
expect(wrapper.findComponent(SelectList).props()).toMatchObject({ disabledIds: [3] })
```

> El stub renderiza `<select-list-stub>` pero conserva las props, así se prueba qué le pasa el padre al hijo. `shallowMount` hace lo mismo con todos los hijos.

## Mocks: `vi.fn`, `vi.spyOn`, `vi.mock`

```ts
vi.mock('../../dia-05/http', () => ({ http: vi.fn<typeof http>() }))   // se hoistea arriba de los imports
vi.mocked(http).mockResolvedValue([])
vi.spyOn(navigator, 'onLine', 'get').mockReturnValue(false)            // getters también
vi.stubGlobal('fetch', vi.fn<typeof fetch>())                          // globals (visto en el día 5)
```

> `vi.mock` reemplaza el módulo para todo el archivo, y `vi.mocked()` solo lo tipa. `restoreAllMocks`/`unstubAllGlobals` en el `afterEach` evitan que un test contamine al siguiente.

## Composables con lifecycle: `withSetup`

```ts
const [online, app] = withSetup(useOnline)   // monta una app vacía que corre el composable
window.dispatchEvent(new Event('offline'))
app.unmount()                                // dispara onUnmounted
```

> Un composable con solo `ref`/`computed` se llama directo. Si usa `onMounted`, `inject` o `onUnmounted` necesita una instancia, y `withSetup` es el patrón de la guía oficial.
